# 사업자별 무선국 허가·기술기준 준수 현황 대시보드

과학기술정보통신부 중앙전파관리소의 **전파관리통계**(공공데이터포털 목록번호 15054180)와
「전파법」·「무선설비규칙」 조문을 결합해, 무선국 허가·신고 현황, 기술기준 위반 건수,
전파사용료를 사업자 축에서 비교하고 기술기준 항목을 사업자 유형별로 매핑하는 대시보드다.

의존성 없는 단일 HTML 한 벌(`index.html`)로 빌드된다. 브라우저에서 바로 열면 된다.

---

## 먼저 알아야 할 것 — 이 대시보드가 사업자별 수치를 비워 두는 이유

전파관리통계는 **전국 총계 17행 × 기간 8열**의 가로형 표다. '구분' 축은 무선국 종류·업무
유형으로 나뉘며 **사업자(법인) 축이 존재하지 않는다**. 따라서 이 통계만으로는 특정 사업자의
허가 건수·기술기준 위반 건수·전파사용료 납부액을 분해할 수 없다.

그래서 이 저장소는 실존 사업자 이름에 근거 없는 수치를 붙이지 않는다. 대신 계층을 나눈다.

| 계층 | 내용 | 실명 사용 | 상태 |
|---|---|---|---|
| **사실 계층** | 사업자 유형별 개설 경로·단말 취급·검사 의무·전파사용료 지위, 기술기준 매핑 | 사용 | 조문으로 확정, 항상 표시 |
| **실적 계층** | 허가 건수·위반 건수·납부액 | 사용 | `PENDING_INPUT` — 원자료 투입 전까지 '미수집' |
| **데모 계층** | 화면 동작 점검용 합성값 | **미사용**(익명 라벨) | 고정 시드로 생성 |

데모 모드는 `이동통신사 A/B/C` 같은 익명 라벨만 쓴다. 합성 수치가 실존 기업 이름에
붙는 일이 없도록 하기 위한 구조다.

## 실데이터 적재

국가 총계를 넣는 경로는 두 가지다. 정규화 규칙은 `scripts/rrb_common.py` 하나를 공유하므로
어느 쪽으로 넣어도 결과가 같다.

### 경로 A — 오픈API (인증키)

자동화에 적합하다. 먼저 포털에서 해당 데이터의 **활용신청**을 하고 인증키를 발급받는다.
발급된 키는 [마이페이지 > 개발계정 상세보기](https://www.data.go.kr/iim/api/selectAPIAcountView.do)
에서 확인한다. 같은 화면의 요청 주소에서 `/api/` 뒤 경로를 그대로 `--path` 로 넘긴다.

```bash
export DATA_GO_KR_SERVICE_KEY='발급받은 Decoding 인증키'
python3 scripts/fetch_rrb_api.py --path '15054180/v1/uddi:xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx'
```

- **인증키는 환경변수로만 다룬다.** 저장소에 커밋하지 않는다. 스크립트는 오류 메시지와
  `--dry-run` 출력에서 키를 항상 가린다.
- 포털은 같은 키를 **Encoding·Decoding 두 형태**로 보여준다. 기본값은 Decoding 키이며
  한 번만 URL 인코딩한다. Encoding 키를 그대로 넣으면 `%2B` 가 `%252B` 로 이중 인코딩되어
  `SERVICE_KEY_IS_NOT_REGISTERED_ERROR` 가 난다 — 그 경우 `--key-is-encoded` 를 붙인다.
- 인증 방식은 `--auth query`(기본, `serviceKey` 파라미터) 와 `--auth header`
  (`Authorization: Infuser`) 를 모두 지원한다.
- `--dry-run` 은 요청 URL만 출력하고 끝낸다.

> **이 데이터에 오픈API가 있는지 먼저 확인할 것.** 15054180 은 포털 목록상 **파일데이터**
> 유형이고, 중앙전파관리소의 API 유형 목록은 2026-07 카탈로그 스냅샷 기준 **0건**이다.
> 파일데이터 오픈API가 별도로 제공되지 않으면 경로 A는 `NO_OPENAPI_SERVICE_ERROR` 를
> 반환한다. 그때는 경로 B를 쓴다.

### 경로 B — CSV 직접 내려받기

1. 공공데이터포털에서 CSV를 내려받는다.
   <https://www.data.go.kr/data/15054180/fileData.do>
2. 정규화 적재한다.
   ```bash
   python3 scripts/ingest_rrb_csv.py 전파관리통계_20260531.csv
   ```

### 공통

매핑되지 않은 '구분' 행은 버려지지 않고 `unmappedSeries` 에 원문 그대로 보존되며
경고가 출력된다. 경고가 뜨면 `scripts/rrb_common.py` 의 `LABEL_RULES` 를 보완한다.

그다음 사업자별 실적 수치를 `data/carrier_metrics.json` 에 채우고, 값마다 `basis` 를 표기한다.
   - `OFFICIAL` — 공표·회신된 원자료 그대로
   - `DERIVED` — 공표 총계와 공표 분모로 산술 도출
   - `ESTIMATED` — 안분 추정(배분식과 근거 지표를 반드시 병기)
4. 다시 빌드한다.
   ```bash
   python3 scripts/build_dashboard.py
   ```

### 사업자별 수치를 구하는 경로

- 과학기술정보통신부·중앙전파관리소 **정보공개청구** 회신
- 국회 과학기술정보방송통신위원회 **국정감사 요구자료**
- 각 사업자 **사업보고서·감사보고서**상 전파사용료 계상액
- 「전파법」 제19조제3항에 따라 전기통신사업자가 통보한 **가입자 수**

## 기술기준 항목

「무선설비규칙」과 「전파법」에서 도출한 15개 항목을 5개 분류로 나눈다.

| 분류 | 항목 |
|---|---|
| 전파의 질 | 주파수 허용편차(제5조·별표1), 점유주파수대역폭 허용치(제6조·별표2) |
| 불요발사 | 스퓨리어스 영역 경계기준(제7조·별표3), 스퓨리어스 영역 불요발사 허용치(제8조·별표4) |
| 공중선전력 | 안테나공급전력 표시·환산비(제9조①·별표5), 허용편차(별표6), 표시방식(제9조②), EIRP/ERP 병기(제9조③) |
| 변조특성 | 변조도·최대주파수편이(제10조①), 최고 통신속도 안정 동작(제10조②) |
| 인체보호·적합성 | 전자파 인체보호기준(전파법 제47조의2), 등급 표시, 기술기준 적합의무(제45조), 준공·정기검사(제24조) |

전체 매트릭스는 [`docs/기술기준-매핑표.md`](docs/기술기준-매핑표.md) 참조.

### 별표 수치를 싣지 않는 이유

구체적 수치 기준(허용편차 값, 불요발사 허용치 등)은 무선설비규칙 **별표 1~6** 및
과학기술정보통신부 고시에 있고 개정이 잦다. 스냅샷을 떠 두면 그 순간부터 오답이 되므로,
이 저장소는 **항목·근거 조문·측정 지표·적용 대상**까지만 정리한다. 판단에 쓸 때에는
조회 시점의 현행 별표를 확인해야 한다.

## 해석할 때 주의할 점

- 전파감시 '기술기준위반'은 **적발 건수**이며 위반의 중대성·조치 결과를 구분하지 않는다.
- 이동통신 가입자 단말은 「전파법」 제19조제2항에 따라 **허가의제**되어 검사·변경허가
  대상에서 제외된다. 무선국 국수 추이는 설비 규모가 아니라 **가입자 수 변동**을 크게 반영한다.
- 제67조제1항제3호에 따라 허가의제 무선국은 전파사용료가 **전부 면제**된다.
  '무선국이 많으면 사용료도 많다'는 해석은 성립하지 않는다.
- 기간통신사업자의 전파사용료는 제68조제1항 단서에 따라 **가입자 수 기준**으로 산정될 수 있어,
  기지국 수 기반 안분 추정은 체계적 편향을 낳는다.
- 포털 목록 메타데이터에서 도출한 항목명은 원본 CSV의 실제 '구분' 문자열과 다를 수 있다.
  적재 시 **원본 라벨이 정본**이다.
